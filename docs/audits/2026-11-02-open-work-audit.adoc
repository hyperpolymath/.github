== 1. PR #24 and Secret Scanner run 41457289788

=== Observed cause

PR #24 proposed `hyperpolymath/smtp-notify-action` v0.5.0 -> v0.5.1. Its
Secret Scanner run https://github.com/hyperpolymath/.github/actions/runs/41457289788[41457289788]
completed with `failure`, created zero jobs, and had no log archive. The run
page annotation is the decisive evidence:

[source,text]
----
Invalid workflow file: .github/workflows/secret-scanner.yml#L22
error parsing called workflow
".github/workflows/secret-scanner.yml"
-> "hyperpolymath/standards/.github/workflows/secret-scanner-reusable.yml@bd0df9ead7faf0cdfe0e13e7966d91e28d0101d4"
: workflow was not found.
----

The REST API still redirects `hyperpolymath/standards` to
`metadatastician/standards`, and the pinned file exists at the canonical
repository. GitHub Actions does not follow that redirect for job-level
`uses:`. The required `scan / gitleaks` context was therefore absent, not
merely failing. This matches the canonical handoff in
`metadatastician/standards/docs/GOVERNANCE-SOURCE-HANDOFF.adoc` and
`docs/decisions/2026-10-27-recovered-session-decisions.adoc`.

The lockfile was not the cause of this particular zero-job run. It was,
however, stale in two ways: `main` still locked smtp-notify-action v0.3.0 while
the workflow used v0.5.0, and PR #24's inline comment still named the v0.2.0
commit `ede1191ef6ff3ac02c4f4d9efdf837ee517e11d7`.

PR #24 was merged by the repository owner at 2026-11-02 19:18 UTC as
`f0f7896e4fd8a05e533a59dc4ee88aaa136fc523`. The merge did not repair the
caller: post-merge Secret Scanner run
https://github.com/hyperpolymath/.github/actions/runs/41508702476[41508702476]
also completed with `failure` and zero jobs. `main` therefore remained broken
after the dependency bump landed.

=== Source repair

PR #25 is the follow-up repair. It keeps the v0.5.1 dependency bump already
merged by PR #24 and repairs the source:

* `.github/workflows/secret-scanner.yml` now calls
  `metadatastician/standards/.github/workflows/secret-scanner-reusable.yml`
  at `8d1a2aab4211493cf42f147f2080f024605797dc`.
* The caller grants only `contents: read` and no longer uses
  `secrets: inherit`; the pinned reusable declares no secrets.
* `.github/workflows/actions.lock` records smtp-notify-action v0.5.1 at
  `e384daf6167a7a7567642d6a62060106244d2413` and the checkout pin used by
  `workflow-contracts.yml`. The reusable-only Secret Scanner caller has an
  empty lock entry: `gh-actions-lock` v0.4.0 does not follow remote job-level
  reusable workflows, and a synthetic through-ref there fails `--verify`.
* `.github/workflows/actions-lock.closure.tsv` remains a reviewed trust
  record for the remote reusable closure. It is advisory while upstream
  `gh-actions-lock` cannot represent that edge.
* The inline smtp-notify-action comment now names the v0.5.1 commit.
* `.github/workflows/workflow-contracts.yml`,
  `.github/scripts/check-workflow-contracts.sh`, and
  `.github/scripts/check_workflow_contracts.py` add YAML-aware regression
  checks for moved reusable coordinates, floating reusable pins, quoted
  `uses:` values, SPDX placement, lockfile coverage, synthetic reusable-only
  lock edges, duplicate YAML keys, and every stale inline notification SHA.

== 2. Issue #13 / D199

D199 adopts automated rebase-onto-base recovery after squash merges. The
appropriate estate-wide service is the `cicd-squabbler` GitHub App webhook
leg, not a community-health workflow in this repository. The App rollout is
already owner-ruled in https://github.com/hyperpolymath/cicd-squabbler/issues/122[cicd-squabbler#122]
(D266/D267: all repositories, owned compute). The webhook leg is still absent
on `main`.

A precise implementation and verification handoff is recorded in
`docs/handoffs/D199-post-squash-stack-recovery.adoc`. No deployment is claimed.
The signing policy rules out the naive implementation: a bot must not
force-push rebased commits, and GitHub rebase-merge replays commits unsigned.
The handoff therefore specifies signed replacement branches/PRs through
GitHub's commit API, conflict escalation, fork handling, concurrency, nested
stacks, and deployment evidence.

== 4. Policy, security, quality, and CI/CD audit

=== Branch policy

Active repository rulesets require linear history, signed commits, and
`scan / gitleaks` (GitHub Actions integration id 15368). Branch-Floor forbids
deletion/non-fast-forward. The secret-scan ruleset has an administrator
bypass actor; this session does not use it. `.github/settings.yml` previously
advertised merge-commit and rebase-merge as allowed, contrary to the live
squash-only policy; it is corrected here.

=== K9 / DEED / Hypatia

This repository currently has no committed `.deed` or `.k9.ncl` payloads and
no fork-governance/Hypatia caller. The canonical K9 and DEED reusable gates
would report zero files unless `require-files: true` is adopted. That is a
coverage gap, not a conformance pass. This audit does not claim K9/DEED
conformance or a Hypatia verdict. The local environment lacked the canonical
Elixir/Hypatia toolchain, and release-asset downloads were blocked by the
sandbox egress policy, so no local Hypatia scan was run.
