# hyperpolymath

Research and engineering across type theory, formal methods, programming-language
design, and the tools that keep a large software estate honest and reproducible.

### What you'll find here

- **Languages & type systems** — experimental cores, checkers, and proofs.
- **Formal methods** — soundness-first tooling that prefers ground truth over
  status docs.
- **Estate infrastructure** — reproducible builds (Guix), provenance, and the
  automation that maintains it.

### Working principles

- 🕳️ **Foundations first** — soundness holes are fixed before features.
- 🔬 **Ground truth** — claims are checked by running the tool, not reading a doc.
- 🪞 **Honest by discipline** — an `AFFIRMATION` snapshot says what is *actually*
  true, and "claim drift" is a reportable issue.

### Getting involved

Issue and discussion templates, a Code of Conduct, and a contributing guide are
shared across every repository from
[`hyperpolymath/.github`](https://github.com/hyperpolymath/.github). Improvements
to those are welcome there.
